## Corresponding source

The complete corresponding source of this binary is, in the hub repository at
the commit above:

1. upstream YYToolkit at the pinned commit (`third_party/yytoolkit/upstream.json`
   carries the full commit id and tree id);
2. these seven patches, from `third_party/yytoolkit/patches/`, applied in the
   order given by `patches/series`:
   1. `0001-runner-interface-scan-hint.patch`
   2. `0002-runner-interface-quiet-init-dump.patch`
   3. `0003-executeit-hook-off-by-design.patch`
   4. `0004-functions-array-validation.patch`
   5. `0005-yyerror-report-once-and-measure.patch`
   6. `0006-release-build-optimised-and-series-identity.patch`
   7. `0007-runner-interface-refuse-unfound-interface.patch`
3. the build tool, `tools/build_yytoolkit.py`, from the same hub commit.

`YYToolkit-BUILD-INFO.json`, committed beside this notice, records the
upstream commit and tree, the hub commit, the sha256 of every patch above, the
toolchain used, and this DLL's own size and sha256 — generated by the build
tool, not hand-written.

## Where to get it

The hub release tagged `yytoolkit-v4.0.1-hs.1` carries this exact DLL together
with its `.sha256`, `YYToolkit-BUILD-INFO.json`, this notice, and a
deterministic zip of `third_party/yytoolkit/` (the patches and the upstream
pin, named by the content of that directory — the exact filename and content
hash are the `source` field of the `YYToolkit-BUILD-INFO.json` shipped
alongside). That release, plus the hub repository itself at the commit above,
together are the corresponding source for this binary.

## Why this is a pointer, not a copy

This directory previously carried two whole-file copies
(`Generic-RunnerInterfaceNew.cpp`, `Hooks.cpp`) and a notice describing a
different, earlier DLL (sha256 `bb113eefc9a5d485231ced1dc85d773dbc6b762ee680214851c56541359ad297`)
as having only those two changes, with "everything else unmodified upstream".
That claim did not hold for that binary — its strings, imports and headers
show changes the notice never listed, and the source behind them could not be
recovered. This binary is not that one and does not repeat that history: it is
built from the patch series named above, every line of which is a reviewed,
committed diff against upstream, not a reconstruction. See
[`docs/agents/yytoolkit-provenance.md`](../../../docs/agents/yytoolkit-provenance.md)
in the hub repository (resolves inside a full toolkit checkout; from a
standalone clone of this repository, use
https://github.com/falorfrozen-cmd/hero-siege-offline-toolkit/blob/main/docs/agents/yytoolkit-provenance.md
instead) for the full account of what was wrong with the previous notice.
